# Bound retries after an accepted stop-report answer (#1662)

The CHECKED T1 gate6635051125 and scoped FIT6634810425 restore the CLI's existing at-most-one-post promise. This changes local host state only, not server law. The real-server trigger for a mismatched read-back remains UNCONFIRMED; red-first uses a fake that alters the stored body/author or hides it.

`.sending` gains optional `acceptedSeq` and `acceptedAuthorWorkerId`. Immediately after `Post` succeeds (including TEAM_CHAT_DUPLICATE's earlierSeq), the reporter atomically replaces the existing intent using the outbox's file sync/rename/directory sync helper. It keeps the frozen body and all previous attempting authors. Read-back and `.reported` happen only after that write succeeds. The accepted author is the worker who received that answer, not necessarily the worker that first created the intent.

On every later run, a recorded sequence takes precedence over the intent age and reconciliation scan. The reporter reads exactly that sequence and compares the frozen body with the recorded accepted author; a different bound reporter can therefore resume it without another post. Any failed/missing/mismatched read stays `failed`, pending, and exit7. A body/author mismatch says `needs a person` (optional D1 taken). Retrying automation only re-reads; a later matching read-back can finish as `reconciled`. No new result word or exit code is introduced; the existing optional outcome `seq` also identifies accepted posts in failed results.

Old `.sending` files without the new fields keep the unknown-answer reconcile/duplicate path. This preserves recovery from transport errors and the existing late-commit residual. A negative recorded seq or missing/unrecorded accepted author fails closed without posting. `.reported` still means a matching body+derived-author read-back, never simply that Post answered.

Limits: there remains a server-answer-to-durable-local-write interval. A crash or storage failure in that interval leaves the old unknown-answer intent, whose reconciliation has the existing ambiguity; this is not an exactly-once journal or a proof against arbitrary disk failure. A persistence error fails the run before read-back/marker, and reports the known seq for operator recovery. Once the accepted seq is durably recorded, retries never post again. No production, real chat, actual host timer, or real-server mismatch trigger is exercised by the author tests.
