# Instructed defect linking (#2449)

`team task link-defect --instruction <kind>:<ref>` forwards a holder instruction through the existing server arm (minimum `696ed50c8`, #4284). This CLI flag creates no platform rule; the defect-link door is described in server schema text (#4280/#4284), while cor:dmo:050:12 names the general App-manager arm. The earlier Proposed cor:agt:130:05 citation was nonexistent and is removed from the affected help.

A separate `TaskLinkDefectInstructed` document adds the required claim without changing the plain document, arguments or six-field JSON receipt. The existing taskClaim parser rejects malformed claims before requests. Only the mutation receives the claim; no lookup is given an instruction or worker session. Empty defect/head checks and all server-owned validation remain in place. Refusals never trigger a retry or plain fallback. An empty link still warns that it may have been recorded and directs the caller to the task's events.

The shared BeginServerTargetInstructedWrite helper snapshots the binding before client creation and verifies it again at send. This door's server resolves the task's App; the CLI checks only binding completeness, same-server identity and stability, leaving App admission to the server. withAsPerson suppresses automatic authored-write attachment, so that middleware cannot borrow a changed binding; the helper alone attaches the verified session. An unavailable or changed binding sends the claim as the signed-in person, checked but not recorded, following instructedAsPerson and the #2457 ruling. No server refusal is retried in that mode.
